# Часть II. Анализ эволюции словаря навыков: v1 → v2 → v3

> Дата анализа: 05.10.2026 (обновлён после добавления датасета LinkedIn) · Файлы: `skills_dict.json` (v1), `skills_dict_v2.json` (v2), `skills_dict_v3.json` (v3, 465 навыков)

## 1. Исходные данные

Словарь навыков расширялся последовательно по **5 датасетам**:

| № | Датасет | Источник | Содержимое | Строк | Размер |
|---|---|---|---|---|---|
| A | `niktigerbill/resume-job-description-fit-ru` | HuggingFace | RU-пары «резюме + вакансия» с меткой соответствия (No/Potential/Good Fit) | 8 000 пар | 56 МБ (parquet) |
| B | `vyacheslavpanteleev1/hhru-it-vacancies-from-20211025-to-20211202` | Kaggle | IT-вакансии HH.ru (окт–дек 2021): название, ключевые навыки, описание | 48 564 | 188 МБ (CSV) |
| C | `sameelie/resume-hh` | Kaggle | Резюме с HH.ru: опыт работы, должности, образование | 44 576 | 455 МБ (CSV) |
| D | `saugataroyarghya/resume-dataset` | Kaggle | Англоязычные резюме: skills, objective, responsibilities, positions | 9 544 | 17 МБ (CSV) |
| E | `arshkon/linkedin-job-postings` | Kaggle | Англоязычные вакансии LinkedIn: title, description, skills | 123 849 | 493 МБ (CSV) |

Всего просканировано **~235 000 записей / ~606 000 текстовых полей** (RU + EN). Датасет E добавлен на финальном шаге (для EN-вакансий) — по нему словарь расширен ещё на 88 навыков.

## 2. Методология

1. **Токенизация** текстов (слова, включая `c#`, `1с`, `44-фз`, `html/css`) и подсчёт частот униграмм и биграмм по каждому корпусу.
2. **Кандидаты в навыки**: список из ~250 терминов (по наблюдениям в корпусах и типовым стекам) проверялся на реальную встречаемость во всех 4 датасетах.
3. **Порог включения**: термин добавлялся при значимой частоте (обычно ≥ 15 упоминаний) и различительной способности; шумные короткие алиасы (`pr`, `r`, `ad`, `go` без контекста) отсекались.
4. **Контроль качества**: проверка уникальности имён, последовательности id, отсутствия пересечения алиасов между навыками (3 конфликта обнаружено и устранено при сборке v3).
5. **Замер покрытия**: для каждой версии подсчитывалось число уникальных найденных навыков на текст с проверкой границ слов.

## 7. Проверки качества

- ✅ id последовательны (1…465), дубликатов имён нет;
- ✅ конфликтов алиасов между навыками нет (при сборке v3 найдено и исправлено 3: `b2b продажи`, `аналитический склад ума`, `исполнительность`; расширение по LinkedIn — 0 новых конфликтов);
- ⚠️ осознанные объединения: Docker ↔ Docker Compose, Виртуализация ↔ VMware/Proxmox, SIEM ↔ Splunk, MS Office ↔ Microsoft 365 — близкие термины намеренно не дублируются, чтобы не задваивать счёт;
- ⚠️ короткие алиасы (`ux`, `ui`, `sas`, `ios`, `pos`, `kpi`) могут давать редкие ложные срабатывания — в боевом использовании стоит применять слово-граничный матчинг (как в замерах) и при необходимости контекстные правила.

- Пересечений сгенерированных текстов с натуральными — 0; дубликаты внутри натуральных — только из исходников.
- Скрипт сборки: `build_datasets.py` (seed=42). Все ссылки на скачивание: см. Часть I.

## 9. Выводы

1. **v3 покрывает ~3.8 навыка на текст против 1.1 у v1** (×3.5) и находит навыки в 57.6% текстов против 35.6% — почти полное покрытие структурированных RU-данных (100%) и высокое для англоязычных резюме (89%).
2. Расширение шло от IT-центричного (v2) к **универсальному словарю рынка труда** (v3): добавлены десятки не-IT доменов, а после LinkedIn — полноценные EN-блоки (медицина, финансы, маркетинг, инженерия, HR), т.е. словарь стал двуязычным (RU+EN).
3. Все добавления **обоснованы реальной частотностью** в корпусах, а не гипотезами, что снижает риск «мёртвых» навыков.
4. На базе корпусов собраны 4 сбалансированных датасета (50/50 natural/synthetic) — пригодны для обучения классификаторов и извлечения навыков.

## 10. Как использовать

```python
import json
skills = json.load(open("skills_dict_v3.json", encoding="utf-8"))

def detect(text, skills):
    t = " " + text.lower() + " "
    found = set()
    for s in skills:
        for a in s["aliases"]:
            i = t.find(a)
            while i != -1:
                b, e = t[i-1], t[i+len(a)]
                if not (b.isalnum() or e.isalnum()):
                    found.add(s["name"]); break
                i = t.find(a, i+1)
    return found

print(detect("Опыт работы: Python, Django, PostgreSQL, Docker", skills))
# {'PostgreSQL', 'Docker', 'Python', 'Django'}
```
